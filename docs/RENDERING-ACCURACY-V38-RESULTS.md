## 구현과 독립 검증

처음에는 v37와 reference GPU/display fingerprint가 같았지만 전체 캡처 도중 display ID·refresh rate(32→60)·선택적 DRIVER_VENDOR 메타데이터가 바뀌어 기존 fingerprint guard가 중단했다. GPU·driver version·backend·DPI·색·bounds는 같다. 부분 결과 218쌍과 닫힌 로그를 capture-attempt-1에, 첫 고정 캡처를 focused-attempt-1과 diagnostics/environment-control-attempt-1에 보존했다. guard를 유지하고 v37 frozen renderer 및 수정 실행기로 고정 48쌍씩 현재 환경에서 다시 캡처해 네 이미지·전체 JSON·raw·판정 불변을 확인한 뒤 전체 캡처를 새로 시작했다. CPU 앱/글리프 성능 실행기·소스·픽셀 해시는 바뀌지 않았다.

native grayscale 글리프에서 양의 가로/세로 배율이 실제로 같을 때만 균일 경로를 쓴다. 작은 양의 축의 절대 차이가 1e-5보다 작더라도 실제 비율은 .5, 2, .75, 4/3일 수 있다. font em에 세로 배율 절댓값을 적용하고 DirectWrite analysis matrix에 signed 가로 비율·세로 방향을 적용하는 기존 방식과 cache key를 유지한다. native off-diagonal 값이 0이 아니면 CPU 경로에서 거부한다. 큰 authored em에서는 작은 shear도 의미 있는 위치 차이를 만들기 때문이다. 일반 텍스트의 기존 epsilon 판정은 유지한다.

36개 변환은 기존 32개와 양의 미세 비균일 배율 (1e-6,2e-6), (2e-6,1e-6), (3e-6,4e-6), (4e-6,3e-6)이다. 큰 authored em을 정상 device em으로 축소한다. saved clip 변환 3개·brush alpha 2개·opacity 3개·RGB 2개·backdrop alpha 4개·clip 3개·AA 2개·run 길이 1/8/9/32·DPI 배율 1/1.5와 조합했다. 반전·배율 변경과 마지막 양의 .5 배율 복귀를 검사한다. 각 glyph의 mask·phase는 별도 DirectWrite 호출로 분석하며 기대값은 독립 double gamma/source-over와 기하학 clip 교집합으로 계산한다. aliased clip은 별도 Direct2D oracle을 사용한다. 엔진 mask/clip cache·blend lookup을 기대값 계산에 쓰지 않는다. 모든 PBGRA byte와 premultiplied 범위를 검사한다. 변경 전 픽셀 실패는 96 DPI 10,244건과 144 DPI 12,980건이다.

17 guard/DPI는 기존 13개와 미세 signed shear 4개다. 작은 shear 1e-6와 큰 authored em을 조합해 이전 CPU 경로의 잘못된 수락·쓰기·후속 paint 오염을 재현한다. 변경 전 guard 검사 assertion 실패 40건, 수정 후 0건이다(40개 변환을 뜻하지 않는다). 수정 후 모든 거부가 무쓰기·무잠금이며 후속 정상 paint가 독립 기준과 같다. 일반 회전/기울임과 layer는 fallback을 유지한다.

반투명 mask 전체가 saved clip 안에 있고 합성 table이 준비되면 별도 noinline ComposeNativeCachedOpacity를 호출한다. 회색 foreground는 mask당 별도 루프를 선택하고 backdrop RGB가 다를 때도 동일한 lookup plane 하나를 사용한다. 키가 자주 바뀌어 table이 준비되지 않은 경로는 축소된 ComposeNativeOpacity를 사용한다. fractional clip과 table 일부 재사용 계산은 유지한다. gamma/합성 table 입력·byte 반올림·캐시 크기·8번째 visible paint 생성 정책은 같다. 새 heap 할당과 table payload 증가는 없다. 첫 경로 분리 시도에서는 고정 불투명도 일부 조건이 최대 10.18% 느려졌고 교대 조건 차이는 작았다. 시도 1의 정확한 헤더·실행기·독립 검사·6회 원값은 diagnostics/attempt-1에 보존했다. 고정/교대 불투명도·RGB 키 변경과 복귀·최초 호출·table 생성·재사용의 최종 성능을 모두 기록한다.

v37의 소스 457개와 비교해 RasterSurface.h와 ScrollRenderingRegression.cpp 두 파일만 바뀌었고 다른 455개는 같다. 측정 헤더와 최종 소스 SHA-256 일치를 확인한다.

## 마지막 회귀·반디집 보관·복원·정리

전체 회귀 12개·platform integrity 통과 후 반디집 ZIP fast level 1로 본 보관본 237,897,074 bytes, 복원 증거 41,112,628 bytes를 만들었다. 보관본 SHA-256과 모든 entry를 확인했다. 새 폴더 소스 457개·비교기 120쌍, 전체 828쌍 새 렌더링의 네 이미지·전체 진단·raw·판정이 원래 실행과 같다. 새 배율/guard 및 기존 여섯 native 명령의 로그 SHA-256도 모두 같다.

복원 검증 후 해시 일치 사본 85,861개·컴파일 생성물 295개·캐시 45,550개를 정리했다. 소스 457개·최신 828쌍과 실패 diff·보호 입력·최소 증거·반디집 보관본 유지. 새 보호 입력 손실 0, 검사 대상 생성물/캐시 0. 과거 두 파일 누락은 기존 보호 기록대로 남긴다.
