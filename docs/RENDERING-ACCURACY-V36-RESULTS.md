## 정확성과 지원 범위

양의 대각 transform과 DPI의 실제 sx/sy를 native grayscale mask에 적용한다. em은 세로 배율, analysis matrix는 가로/세로 비율과 quarter-pixel phase를 사용한다. mask cache key에 이 비율을 추가해 다른 폭 또는 복귀한 폭이 틀린 mask를 재사용하지 않도록 했다. 기존 균일 배율은 matrix 1을 유지한다. 단일 mask cache는 여전히 16 MiB·4,096 entry 제한이며 immutable face 소유와 run의 shared ownership을 유지한다. 마지막 native mask의 전체 key가 같으면 tree 조회 없이 같은 entry를 재사용하며, eviction 때 이 참조도 해제해 별도 texture 용량을 늘리지 않는다. [Microsoft CreateGlyphRunAnalysis 문서](https://learn.microsoft.com/en-us/windows/win32/api/dwrite_2/nf-dwrite_2-idwritefactory2-createglyphrunanalysis)의 em 이후 transform 적용 순서를 따른다.

10개 draw transform(가로 .5/2, 세로 .5/2, .75×1.25, 1.25×.75, 가로 .125/8, 균일 제어, .5 복귀)×clip transform 3개×brush alpha 2개×opacity 3개×RGB 2개×backdrop alpha 4개×clip 3개×AA 2개×run 길이 4개(1/8/9/32)×DPI 배율 2개를 검사한다. 각 glyph phase의 mask를 별도 DirectWrite 호출로 읽고 독립 double gamma/source-over와 기하학적 clip 교집합을 계산한다. aliased clip은 별도 Direct2D oracle을 쓴다. 엔진 mask/clip cache와 blend lookup을 기대값 계산에 쓰지 않는다. 전체 PBGRA bytes와 premultiplied 범위를 비교한다.

회전·skew·음수/0 축·NaN/Inf·비율 범위 밖·overflow, 일반 텍스트의 비균일 배율은 fallback하며 픽셀을 쓰거나 표면을 잠그지 않는지 확인했다. 유효 입력으로 복귀한 결과도 byte 단위로 같다. native 가로/세로 비율 지원은 .125~8이다. 전체 affine/CSS transform 계약은 미완료다.
