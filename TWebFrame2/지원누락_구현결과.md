# 지원 누락 항목 구현 및 검증

작성일: 2026-10-02

대상: 작업 폴더 루트의 `TWebFrame2_지원누락_함수문법_목록.md`에 열거된 문법 2항목, 동작 오류 6항목, 공개 API 경로 19개.

**목록의 최소 재현 오류 8개를 수정하고, 19개 공개 경로에 실제 기능을 추가했다.** API 이름만 등록하거나 성공 값을 고정 반환하는 방식으로 처리하지 않았다. 대규모 플랫폼 API의 세부 지원 범위와 미지원 기능은 아래에 명시한다.

## 수정 범위

- 이번 작업의 소스, 의존성, 검사 코드와 결과 문서는 모두 `D:\ai_works\miniwebbrowser\TWebFrame2` 아래에 있다.
- 공통 컴파일러·VM·객체 모델, Worker 실행 환경, BrowserContext의 origin별 저장소와 기존 DOM/Canvas/Layout/View 경로를 사용한다.
- 페이지 URL, 사이트 이름, 보안 스크립트 문자열에 따라 결과를 바꾸는 분기를 추가하지 않았다.
- 작업 전에 존재하던 수정과 수집 자료를 보존했다. 루트의 누락 목록은 변경하지 않았다.

## 문법 및 공통 실행 규칙

| 목록 항목 | 구현 결과 |
| --- | --- |
| 배열 구조 분해의 `...rest` | 선언·매개변수의 배열 패턴과 iterable 입력을 처리하고 나머지 요소를 새 배열에 담는다. |
| 클래스의 `async()` 메서드 이름 | 문맥에 따라 `async` 수정자와 일반 메서드 이름을 구별한다. `static()` 이름도 같은 규칙을 적용한다. |
| 선언되지 않은 변수 | 읽기와 호출은 `ReferenceError`로 처리한다. `typeof`는 기존 표준 동작대로 `undefined`를 반환한다. |
| `const` 재할당 | 환경별 불변 바인딩을 검사한다. 일반 대입, 증감, closure, 반복문에서 `TypeError`를 발생시킨다. 최적화 경로가 이 검사를 우회하지 않도록 한다. |
| `super` 메서드 | 기반 클래스에서 메서드를 찾아 파생 객체의 `this`로 호출한다. |
| 정규식 `u` | UTF-16 인덱스와 Unicode 코드 포인트 소비를 구별한다. supplementary character 매칭과 빈 매치의 Unicode 진행을 처리한다. |
| 이름 있는 캡처 | `exec`·`match`의 `groups`, 치환의 `$<name>`, 콜백 인자를 처리한다. |
| 후방 탐색 | 공통 정규식 경로에서 긍정·부정 lookbehind를 처리한다. |

정규식은 `RuntimeRegex.h`와 `StringRegex.inl`을 통해 공통 처리한다. `RegExp.exec/test`, 문자열의 `match/search/matchAll/split/replace`가 같은 매칭 구현을 사용한다. `lastIndex`, `g/y`, `d` 인덱스, `RegExp.prototype.exec`, 실제 `matchAll` iterator도 회귀검사에 포함했다.

## 공개 함수 및 API

| 공개 경로 | 구현한 동작 |
| --- | --- |
| `Object.getOwnPropertyDescriptors` | 기존 descriptor 규칙으로 문자열·Symbol 키의 own descriptor를 수집한다. |
| `Reflect.getOwnPropertyDescriptor` | 공통 descriptor를 조회하고 primitive 대상은 `TypeError`로 거절한다. |
| `FinalizationRegistry` | 약한 target/token, held value, register/unregister, 공통 GC 이후 비동기 cleanup을 처리한다. 순환 객체 수집 후 cleanup 실행을 확인했다. |
| `RegExp.$1` | 최근 캡처를 반영한다. `$2`~`$9` 및 기본 legacy match 속성도 갱신한다. |
| `AudioContext` | oscillator/gain/buffer source 연결, 기본 parameter와 시간 예약, suspend/resume/close, waveOut 출력 경로를 구현했다. OfflineAudioContext의 실제 PCM 파형도 계산한다. |
| `File` | Blob 부분 결합과 바이너리 보존, name/type/size/lastModified, text/arrayBuffer, 기존 FileReader의 data URL 읽기를 지원한다. |
| `FileList` | DOM input·DataTransfer에서 해당 인터페이스, length/인덱스/item/iterator를 제공한다. 직접 생성은 표준처럼 거절한다. |
| `MessageChannel` | 연결된 두 MessagePort, task queue 전달, structured clone, ArrayBuffer 전송·분리, start/close 및 이벤트를 처리한다. |
| `OffscreenCanvas` | 기존 공통 Canvas 2D 엔진에 연결한다. 실제 픽셀 그리기·읽기와 PNG Blob 인코딩을 지원한다. |
| `WebAssembly` | 네이티브 wasm interpreter와 오류·validate·Instance 인터페이스를 연결했다. |
| `WebAssembly.Module` | BufferSource를 파싱하고 명령 타입을 검사한다. |
| `WebAssembly.compile` | 실제 Module 또는 실패 Promise를 반환한다. |
| `WebAssembly.instantiate` | Module/bytes 입력에 따라 Instance 또는 module/instance 결과를 반환한다. 함수 실행, JS 함수 import, 공유 memory view를 확인했다. |
| `document.featurePolicy` | 지원 feature 목록 조회와 origin·부모 iframe의 `allow`에 따른 허용 조회를 구현했다. |
| `navigator.sendBeacon` | 공통 HTTP 요청 경로에 POST를 큐잉한다. 자격 증명과 64 KiB 대기 body 제한을 적용한다. 반환값은 큐잉 성공 여부다. |
| `navigator.storage` | origin 저장소의 실제 usage/quota 조회 및 persistence 상태를 제공한다. persistence 허가는 부여하지 않으므로 persist/persisted는 false다. |
| `navigator.storage.getDirectory` | 안전한 origin의 OPFS를 제공한다. 디렉터리·파일 핸들, 읽기/쓰기/seek/truncate/abort/close, Worker 전용 sync access handle을 구현했다. 같은 BrowserContext의 페이지·Worker가 같은 origin 파일을 공유한다. |
| `trustedTypes` | 별도 native 타입의 TrustedHTML/Script/ScriptURL, 타입 판정 및 기본 sink 타입 조회를 제공한다. |
| `trustedTypes.createPolicy` | 실제 정책 콜백을 호출해 typed 결과를 만든다. 미등록 규칙과 중복 정책은 오류로 처리한다. |

OPFS는 origin별 64 MiB quota와 쓰기 잠금을 적용한다. recursive 삭제도 하위 파일의 잠금을 확인한다. `BrowserContext(profileDirectory)`를 사용하는 프로필에서는 origin별 snapshot을 저장·재개하며, 기본 메모리 컨텍스트에서는 해당 컨텍스트 수명 동안 유지된다.

## DPI 100%·150%

CSS px와 DOM 기하 좌표는 DIP로 유지하고, 실제 픽셀 좌표 변환은 기존 공통 DPI 경로를 사용한다. 자식 View가 받는 `WM_DPICHANGED_AFTERPARENT`를 처리하도록 추가했으며, `WM_DPICHANGED`와 함께 렌더 타겟·장치 리소스를 폐기한 뒤 viewport, JS devicePixelRatio, 대화상자와 레이아웃을 갱신한다.

96 DPI와 144 DPI의 실제 Direct2D 렌더 타겟에서 다음을 확인했다.

- 일반 grid·button CSS 크기와 간격, DOM `getBoundingClientRect`, 클릭 hit test 좌표.
- 픽셀 배경색과 100%↔150% relayout 후 CSS 크기 유지.
- 기존 스크롤, 넘친 자식 요소, stacking/clip 및 자식 frame의 한글·영문 텍스트 렌더링.

스크롤 검사 fixture에는 투명한 위쪽 border를 추가했다. 자식의 margin이 부모와 collapse되지 않게 하여, 원래 검사 목적대로 부모는 화면 밖에 있고 넘친 자식만 화면 안에 있게 한다.

이는 DPI 렌더 타겟을 사용하는 자동검사다. 운영체제의 배율 설정을 수동으로 바꾸거나 실제 두 모니터 사이에서 창을 이동하는 검사는 수행하지 않았다.

## 세부 지원 한계

이번 수정은 목록에 열거된 경로와 검증한 동작을 구현한 것으로, 플랫폼 API 전체의 표준 적합성 완료를 의미하지 않는다.

- WebAssembly는 wasm3가 처리하는 core instruction을 지원한다. table export와 memory/global import는 명시적으로 거절하며 SIMD·threads·GC 등 최신 확장은 미지원이다. 메모리 256 MiB, stack 1 MiB 제한이 있다.
- AudioContext는 기본 합성·버퍼 재생 경로다. decodeAudioData, analyser, filter 등 전체 Web Audio 노드는 미지원이다. 오디오 장치의 실제 소리 출력은 시험하지 않았으며, offline PCM 결과를 시험했다.
- OffscreenCanvas는 2D·PNG 경로다. WebGL, ImageBitmap 및 canvas 이전 기능은 미지원이다. MessagePort를 Worker에 이전하는 기능도 미지원이다.
- featurePolicy는 iframe `allow` 기반 조회의 제한된 feature 집합을 지원한다. HTTP Permissions-Policy 전체 처리를 구현한 것은 아니다. trustedTypes는 정책 콜백과 typed 결과를 제공하지만 CSP의 `require-trusted-types-for` 강제 적용은 미지원이다.
- sendBeacon의 탐색 종료 후 전송 유지, FormData body 및 모든 CORS MIME 조합은 이번 검증 범위 밖이다. 기존 FileReader의 동기 이벤트 방식도 유지했다.
- PCRE2 기반 정규식은 목록의 Unicode·named group·lookbehind 오류를 해결했지만 ECMAScript와 PCRE2 간 전체 문법 차이, lone surrogate 등 모든 edge case의 일치까지 보장하지 않는다.
- 최종 서버 판정이나 특정 사이트의 보안 확인 통과를 검사하지 않았다.

네이티브 의존성 버전·라이선스·변경 내용은 `vendor/README.md`에 기록했다. 파일 API 구현 시 참고한 기준은 [WHATWG File System](https://fs.spec.whatwg.org/)과 [Storage](https://storage.spec.whatwg.org/)이며, 정규식·불변 바인딩·정리 콜백의 기준은 [ECMAScript](https://tc39.es/ecma262/)다.
